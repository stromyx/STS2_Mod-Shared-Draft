## 游戏崩溃修复（SIGABRT）
- **问题**: 启动游戏后直接崩溃，日志显示 `BUG: Unreferenced static string to 0: _initialize` 等错误
- **发现**:

  2. 手动添加 `GodotSharp.dll` 引用（从游戏 data 目录）
  3. 将 `ModEntry` 从 `partial class : Node` 改为 `static class`（不继承 Godot 类）
  4. 将 `GoldGiftPanel` 从 `partial class : PanelContainer` 改为 `static class`（用组合代替继承）
  5. 将 `GoldGiftButton` 从 `partial class : Button` 改为 `static class`（工厂模式创建 Button）
  6. 更新 `TopBarPatch` 和 `GoldSyncPatch` 的引用
- **关键教训**: StS2 mod 必须使用 `Microsoft.NET.Sdk`，不能用 `Godot.NET.Sdk`（官方模板 ModTemplate-StS2 也是如此）
- **编译输出路径变为**: `bin/Debug/net9.0/GoldGift.dll`（31KB，比之前的 40KB 更小）

## 切换到 public-beta v0.99.1 + Godot.NET.Sdk 编译
- **游戏版本**: 切换到 public-beta v0.99.1（data 目录从 `data_Slay the Spire 2_x86_64` 变为 `data_sts2_macos_x86_64`）
- **v0.99.1 Mod 加载机制变化**:
  - `ReadModsInDirRecursive` 扫描目录下所有 `.json` 文件作为 manifest（config.json 被误扫但不阻塞）
  - `TryLoadMod` 使用 `AssemblyLoadContext.LoadFromAssemblyPath` 加载 DLL（而非旧版的 `Assembly.LoadFrom`）
  - `CallModInitializer` 查找 `[ModInitializerAttribute]` 标记的类+方法，调用静态初始化方法
  - 如果没有 `ModInitializerAttribute`，自动调用 `Harmony.PatchAll`
- **csproj 关键修改**:
  - SDK: `Microsoft.NET.Sdk` → `Godot.NET.Sdk/4.5.1`
  - 新增 `<DisableImplicitGodotGeneratorReferences>true</DisableImplicitGodotGeneratorReferences>` — 禁用 Godot source generator（避免生成 GodotPlugins.Game/ScriptManagerBridge）
  - 新增 `<GenerateAssemblyInfo>false</GenerateAssemblyInfo>`
  - 移除手动 `GodotSharp.dll` 引用（Godot.NET.Sdk 自动提供 GodotSharp NuGet 包）
  - 保留 `0Harmony.dll` 和 `sts2.dll` 手动引用
- **核心思路**: 使用 `Godot.NET.Sdk` 获得 GodotSharp 自动引用和 Godot 类型支持，但通过 `DisableImplicitGodotGeneratorReferences=true` 禁用 source generator，防止生成与游戏冲突的初始化代码
- **输出路径变化**: Godot.NET.Sdk 将输出重定向到 `.godot/mono/temp/bin/Debug/`（不再是 `bin/Debug/net9.0/`）
- **编译结果**: GoldGift.dll (30KB)，不含 GodotPlugins/ScriptManagerBridge，引用 GodotSharp/0Harmony/sts2
- **部署**: 自动复制到 mods/GoldGift/（GoldGift.dll + GoldGift.json + GoldGift.pck + config.json）
- **关键发现**:
  - `DisableGodotGeneratedScripts` 在 Godot 4.5.1 SDK 中不起作用
  - 正确的属性名是 `DisableImplicitGodotGeneratorReferences`（在 `Sdk.targets` 中控制 `Godot.SourceGenerators` 包引用）
  - `GodotDisabledSourceGenerators` 是 `CompilerVisibleProperty`，可以精确控制禁用特定 generator
  - Godot.NET.Sdk 包缓存在项目目录 `packages/godot.net.sdk/4.5.1/` 下

## GoldGift 崩溃原因分析
- **根因**: Harmony patch 了 Godot 引擎生命周期方法 `NTopBar._Ready()` 和 `NRun._Ready()`，这些方法经过 Godot C++ native → GDExtension bridge → C# 的调用链，Harmony 的 JIT 蹦床注入会破坏该调用链
- **次要因素**: 大量动态 Godot UI 创建（CanvasLayer/PanelContainer/SpinBox 等）、反射访问内部 API、PCK 文件加载
- **对比**: StartingGold 只 patch 纯 C# 静态方法 `Player.CreateForNewRun`，不涉及 Godot native 调用路径
- **修复方向**: 不要 Harmony patch `_Ready()`，改用 `CallDeferred` 延迟注入 UI；先禁用 PCK；减少反射
