# 2026-03-20 工作日志

## 研究：游戏原生多人宝箱遗物拾取 + 石头剪刀布动画系统

### 反编译分析的关键类（sts2.dll）

**1. NMultiplayerVoteContainer — 遗物上的玩家投票头像容器**
- 命名空间：`MegaCrit.Sts2.Core.Nodes.CommonUi`
- 场景路径：`res://src/Core/Nodes/CommonUi/NMultiplayerVoteContainer.cs`
- 使用 `SceneHelper.Instantiate<TextureRect>("ui/multiplayer_vote_icon")` 实例化投票图标
- 投票图标使用 `player.Character.IconTexture` 和 `player.Character.IconOutlineTexture`
- 关键方法：
  - `Initialize(PlayerVotedDelegate del, IReadOnlyList<Player> players)` — 初始化
  - `RefreshPlayerVotes(bool animate)` — 刷新投票显示
  - `BouncePlayers()` — 弹跳动画
  - `SetPlayerHighlighted(Player, bool)` — 高亮放大1.25x
- 动画：
  - AnimVoteIn: `modulate:a` 0→1 (0.2s) + `position:y` 20→0 (0.3s, Back ease)
  - AnimVoteOut: `modulate:a` →0 (0.1s, delay 0.15) + `position:y` →20 (0.25s, Expo ease)
  - BouncePlayers: `scale` →1.3 (0.15s) + `position:y` →-10 (0.15s) → 然后回弹

**2. NTreasureRoomRelicHolder — 宝箱遗物持有者**
- 命名空间：`MegaCrit.Sts2.Core.Nodes.Screens.TreasureRoomRelic`
- 继承 `NButton`，包含 `NMultiplayerVoteContainer VoteContainer` + `NRelic Relic`
- `_Ready()` 中通过 `GetNode<NMultiplayerVoteContainer>("%MultiplayerVoteContainer")` 获取
- `Initialize(RelicModel, IRunState)` — 设置遗物 + 初始化 VoteContainer
- `AnimateAwayVotes()` — 在发奖时动画移除投票标记
- 有 uncommon/rare 发光粒子效果 (`GpuParticles2D`)

**3. NTreasureRoomRelicCollection — 遗物合集 + 猜拳动画编排**
- 命名空间：`MegaCrit.Sts2.Core.Nodes.Screens.TreasureRoomRelic`
- 包含 `_fightBackstop`（猜拳背景遮罩）和 `_hands`（NHandImageCollection）
- 核心流程：
  - `InitializeRelics()` — 从 TreasureRoomRelicSynchronizer 获取遗物列表
  - `PickRelic(holder)` → `synchronizer.PickRelicLocally(holder.Index)`
  - `RefreshVotes()` — 监听 `VotesChanged` 事件刷新
  - `AnimateRelicAwards(results)` — 结算动画编排：
    1. 按 ResultType 排序（OnlyOnePlayerVoted → FoughtOver → ConsolationPrize）
    2. **FoughtOver**：holder 移动到屏幕中心 + `_fightBackstop` 显示 → `_hands.DoFight(result, holder)`
    3. **非冲突**：`hand.GrabRelic(holder)` 手抓遗物动画
    4. 最后 `_hands.AnimateHandsAway()` + `RelicCmd.Obtain()` 发遗物

**4. NHandImageCollection — 手势动画集合控制器**
- 管理所有玩家的 NHandImage 节点
- 关键方法：
  - `BeforeFightStarted(List<Player>)` — 设置参战玩家的手为战斗模式
  - `DoFight(RelicPickingResult, holder)` — 核心猜拳动画循环：
    - 遍历每一轮 `fight.rounds`
    - 每轮：所有参战玩家同时执行 `hand.DoFightMove(move, duration)` — 手摆动+揭示出招
    - 速度递进：`durationMultiplier = 1.5 / (round + 1.5)` — 越到后面越快
    - 输家执行 `DoLoseShake(player, duration)` — 抖动+变灰
    - 最后一轮：等待0.5s → 胜者 `hand.GrabRelic(holder)` 抓走遗物
  - `AnimateHandsIn()` / `AnimateHandsAway()` — 手进出动画

**5. NHandImage — 单个玩家的手势图片节点**
- 场景路径：`ui/hand_image`
- 通过 `PreloadManager.Cache.GetScene(_scenePath).Instantiate<NHandImage>()` 创建
- 包含 `_textureRect`（TextureRect）和 `_grabMarker`（Marker2D）
- 关键坐标：`_pointingPivot = (163, 10)`, `_fightingPivot = (197, 600)`
- 4个玩家位置：Index % 4 → 0:底部, 1:左侧, 2:右侧, 3:顶部
- **SetTextureToFightMove(move)** — 切换手势贴图：
  ```
  Rock     → player.Character.ArmRockTexture
  Paper    → player.Character.ArmPaperTexture
  Scissors → player.Character.ArmScissorsTexture
  ```
- **DoFightMove(move, duration)** — 摆动动画（3次上下摆动 + 最后揭示出招）
  - 初始显示 Rock，交替摆动 rotation ±π/10（带随机抖动）
  - 最后一次摆动后切换到实际出招贴图
- **GrabRelic(holder)** — 手伸出抓遗物：
  - 切换到 Paper（张开手），移动到遗物位置 (0.5s, Sine)
  - 切换到 Rock（握拳），Reparent 遗物到手上
  - 收回到原位 (0.5s, Sine)
- **DoLoseShake(duration)** — 输者抖动+变灰 (ScreenRumbleInstance)

**6. RelicPickingResult / RelicPickingFight — 猜拳数据结构**
- `RelicPickingResult.GenerateRelicFight(List<Player>, RelicModel, Func<RelicPickingFightMove>)` — 核心API
- 循环机制：remainingPlayers > 1 时持续出招，每轮淘汰"输"的一方
  - 如果3种都出现 → 平局，重打
  - 如果2种出现 → 按规则淘汰（`(move1 + 1) % 3 == move2` → move1 输）
- `RelicPickingFightMove`：Rock=0, Paper=1, Scissors=2
- `RelicPickingResultType`：OnlyOnePlayerVoted, FoughtOver, ConsolationPrize

### 关键发现总结
1. **投票头像**使用 `SceneHelper.Instantiate<TextureRect>("ui/multiplayer_vote_icon")` 预制场景
2. **手势动画**使用 `ui/hand_image` 预制场景 + `Character.ArmRockTexture/ArmPaperTexture/ArmScissorsTexture`
3. 每个角色有**独立的手臂贴图**（石头/布/剪刀各一张）
4. 动画编排是**异步的** async/await + Tween 组合
5. **所有UI节点**都是原生 Godot 场景 (.tscn)，可以通过 `SceneHelper.Instantiate` / `PreloadManager.Cache.GetScene` 加载
6. **mod 可以直接复用**这些预制场景和 Character 贴图资源
