# 2026-03-20 工作日志

## Bug Fix: 跳过选卡后 CardReward 按钮消失

**问题**: 玩家在共享选卡界面点击"跳过"后，CardReward 按钮从奖励界面消失，无法再通过原版流程选卡。

**根因**: `RunDraftFlowAsync` 完成时无条件调用 `_draftCompletionSource?.TrySetResult(true)`，`true` 表示"移除 CardReward 按钮"。但对于跳过选卡的玩家，他们没有获得卡牌，CardReward 不应该被移除。

**修复**: 在 `SharedDraftManager.cs` 的 `RunDraftFlowAsync` 中，draft 完成时检查本地玩家是否真正获得了卡牌（`IsCompleted && !IsOptedOut && IsAwarded`）。只有真正获卡的情况才返回 `true`（移除 CardReward），否则返回 `false`（保留按钮，让玩家可以通过原版流程选卡）。

**影响文件**: `SharedDraft/SharedDraftManager.cs` — `RunDraftFlowAsync` 方法的完成部分（约第978行）

## Bug Fix (v2): 跳过后共享 draft 提前结束，无法再进入共享卡池

**问题**: 上一个修复只解决了 CardReward 按钮保留问题，但 draft 本身仍然会在其他玩家完成后提前结束（`Reset()` 清空状态）。跳过的玩家再进入时，`HasRegisteredRewards()` 返回 false，走原版流程而非共享 draft。

**根因** (3处):
1. `ResolveAndAwardOneRound` 中每轮结算会把 opted-out 玩家标记为 `IsCompleted = true`，导致 loop 退出条件误判为"所有玩家都完成了"
2. Settlement loop 退出条件只检查活跃玩家，不考虑 opted-out 但未获卡的玩家
3. `AllActivePlayersSelected()` 在无活跃玩家时因 LINQ `.All()` 空集合返回 true，导致空转

**修复**:
1. **不再标记 opted-out 为 completed**: 删除 `ResolveAndAwardOneRound` 中把 opted-out 玩家标记完成的代码。opted-out 玩家保持 `IsOptedOut` 状态，可随时通过 CardReward 按钮回来
2. **修改 loop 退出条件**: 只在「所有玩家都获卡」或「卡池耗尽」时退出。有 opted-out 未获卡玩家时，draft 保持 alive 等待重新进入
3. **修复 AllActivePlayersSelected**: 无活跃玩家时返回 false 而非 true
4. **增加 maxRounds**: 10 → 50，容纳多次 opt-out/re-entry 循环

**影响文件**: `SharedDraft/SharedDraftManager.cs` — `ResolveAndAwardOneRound`、settlement loop 退出条件、`AllActivePlayersSelected`

## Bug Fix (v3): debug 模式下跳过后 CardReward 按钮入口消失

**问题**: debug 模式下玩家点击跳过后，CardReward 按钮无法再次点击。

**根因**: `HandleCardRewardSelect` 返回的 `Task<bool>`（由 `_draftCompletionSource` 提供）在 opt-out 后未完成。原版 RewardsScreen await 这个 Task，在 Task 未完成期间整个奖励界面处于等待状态，CardReward 按钮不响应点击。

**修复**: `SubmitLocalOptOut` 中，先完成旧的 `_draftCompletionSource`（`TrySetResult(false)` → 保留 CardReward 按钮），然后创建新的 `_draftCompletionSource` 供 re-entry 使用。同时更新 `HandleCardRewardSelect` 的 re-entry 检测逻辑：用 Phase 状态而不是 TCS.Task.IsCompleted 来判断 draft 是否仍在进行。

**影响文件**: `SharedDraft/SharedDraftManager.cs` — `SubmitLocalOptOut`、`HandleCardRewardSelect`

## Bug Fix (v4): debug 模式下猜拳总是本地玩家赢

**问题**: debug 模式下发生选卡冲突时，猜拳（RPS）结果总是本地玩家获胜。

**根因**: `RunRockPaperScissors` 中，debug 模式下虚拟玩家的 `comp.Player` 要么是 null 要么是本地玩家的引用（从 `InitializePlayerStates` 中获取 `players[i]`，但在单人 debug 中只有一个真实玩家）。当所有 `fighterPlayers` 都引用同一个 Player 对象时，`GenerateRelicFight` 返回的 winner 通过 `c.Player == winnerPlayer` 引用比较映射回 competitors，总是匹配到第一个（slot 0 = 本地玩家）。

**修复**: debug 模式下直接使用 `RunRpsFallback`（`new System.Random()` 随机选 winner），跳过 `RunRpsViaGameApi`。后者依赖 Player 引用唯一性，在 debug 模式下不成立。

**影响文件**: `SharedDraft/SharedDraftManager.cs` — `RunRockPaperScissors`

**影响文件**: `SharedDraft/SharedDraftManager.cs`、`SharedDraft/UI/SharedDraftScreen.cs`

## Debug 诊断 (v5.2): 添加 [DIAG] 标签日志定位 opt-out → re-entry 断点

**背景**: v3/v4 修复（opt-out TCS 替换 + RPS 随机化）理论上逻辑正确，但用户报告仍然有问题。添加诊断日志定位实际运行时的断点。

**影响文件**: `SharedDraft/SharedDraftManager.cs`、`SharedDraft/Patches/RewardsPatch.cs`

- 访问链路: `RunManager.Instance` → `Run` (NRun) → `SubmenuStack`

完全重写 `DraftInputHandler.IsAnyNativeScreenOpen()`，使用三层策略：
1. 反射访问 `NRunSubmenuStack.IsScreenOpen`/`ScreenCount`（缓存反射结果）
2. `SceneTree.Paused` 检查（暂停菜单兜底）
3. 轻量扫描 `NSettingsScreenPopup` 名称节点
