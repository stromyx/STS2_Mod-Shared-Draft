## ModConfig 注册不生效 — 修复 ConfigEntry[] 数组类型
- **根本原因**：`new[] { MakeEntry(...), ... }` 创建的是 `object[]`，而 `ModConfigApi.Register()` 第三个参数类型是 `ConfigEntry[]`。反射 `GetMethod("Register", new[] { typeof(string), typeof(string), entries.GetType() })` 中 `entries.GetType()` = `object[]`，不匹配 `ConfigEntry[]`，`GetMethod` 返回 null → 注册静默失败
- **修复**：用 `List<object>` + `Array.CreateInstance(_entryType!, count)` 创建正确类型的 `ConfigEntry[]` 数组
- **增加日志**：`IsAvailable == false` 时打印 "ModConfig not detected, skipping registration."，方便诊断

## 帧率严重下降 — 修复 ProcessFrame 事件无限累积泄漏
- **根本原因**：三个 mod 的 `ModEntry.Initialize()` 中使用 `tree.ProcessFrame += () => { tree.ProcessFrame += () => Register(); };` 注册 ModConfig
  - **外层 lambda** 永远挂在 `ProcessFrame` 上（从不取消订阅），每帧触发
  - 每帧触发时，又往 `ProcessFrame` **追加一个新的内层 lambda**
  - 结果：内层 lambda 数量线性增长（第 N 帧有 N-1 个），每帧调用 `Register()` 的次数 = N-1
  - 游戏运行 1 分钟（~3600 帧@60fps），每帧调用 ~3600 次 `Register()`，产生海量日志字符串分配和反射开销
  - **三个 mod 都有此 bug** = 问题 ×3
- **修复**：
  1. 将 `tree.ProcessFrame += lambda` 改为 `tree.CreateTimer(0).Timeout += lambda`（一次性定时器，触发后自动销毁）
  2. 给 `ModConfigBridge.Register()` 添加 `_registered` 布尔守卫，确保只执行一次
