## GoldGift + SharedDraft 核心网络 Bug 修复 — 自定义 INetAction

### 问题诊断
- **GoldGift**：发送者金币减少但接收者不增加
  - 根因：`NetPickRelicAction.Serialize()` 使用 `writer.WriteInt(relicIndex, 8)` — 只有 8 位！
  - 值 >255 被截断：如 5199 % 256 = 79, 5101 % 256 = 237（与 Windows 日志完全吻合）
- **SharedDraft**：战斗后不出现共享选牌界面
  - 根因1：`RewardsPatch.OfferPatch` 是 Prefix，读取 `CardReward.Cards` 时卡牌尚未生成 → draft pool = 0 cards
  - 根因2：网络通信同样受 8 位截断影响

### 修复方案 — 自定义 INetAction（32位序列化）
- **关键发现**：`ActionTypes` 静态构造器调用 `ReflectionHelper.GetSubtypesInMods<INetAction>()`，自动发现并注册 mod DLL 中的自定义 INetAction 类型
- **GoldGift**：新建 `NetGoldGiftAction.cs`
  - struct 实现 `INetAction` + `IPacketSerializable`
  - `writer.WriteInt(encodedGift, 32)` — 完整 32 位序列化
  - 编码：`sender*10000 + target*1000 + amount`（支持 amount 1-999）
  - 配套 `GoldGiftGameAction` 类执行金币转移
- **SharedDraft**：新建 `NetDraftAction.cs`
  - struct 实现 `INetAction` + `IPacketSerializable`
  - `writer.WriteInt(encodedValue, 32)` — 完整 32 位序列化

  - 配套 `DraftGameAction` 类处理 ready 和 selection
- **SharedDraft RewardsPatch**：`OfferPatch` 从 Prefix 改为 Postfix（Cards 在 Offer 内部 GenerateWithoutOffering 后才有值）
- **MaxAmountPerAction**：从 99 提升到 999

### 问题回顾

## GoldGift 按钮点击无法打开面板 — 修复

### 问题分析
按钮点击有 UI 变化（hover/pressed 样式生效），但 `GoldGiftPanel.Toggle()` 从未被调用（日志中无任何 Toggle 相关输出）。

**根因**：Godot 4 的 GUI 输入传播顺序是**从子节点到父节点**。按钮是 `_dragHandle` 的子节点，按钮的 `MouseFilter` 默认是 `Stop`，所以按钮会消费所有鼠标事件，**`_dragHandle` 的 `GuiInput` 永远收不到按钮区域内的点击**。

之前的设计意图是通过 `_dragHandle.GuiInput` 统一处理拖拽和点击，但实际上 `_dragHandle` 根本收不到输入（被子节点 Button 拦截了）。而按钮的 `Pressed` 信号又没有连接到 Toggle（代码注释说"avoid double-triggering"）。

### 修复方案
- **完全重构输入架构**：
  - `_dragHandle.MouseFilter = Ignore`（不接收任何输入）
  - 所有输入处理放在 `_button.GuiInput += OnButtonGuiInput`
  - `_button.MouseFilter = Stop`（按钮负责接收所有输入）
  - 不连接 `btn.Pressed` 信号，而是通过 `GuiInput` 手动检测 mousedown/mouseup
  - 点击 vs 拖拽逻辑不变（mousedown 记录起始位置，移动超阈值则为拖拽，否则 mouseup 触发 Toggle）
  - 拖拽时修改 `_dragHandle.Position`
- 在 Toggle() 和 OnButtonGuiInput 中添加日志便于调试

## SharedDraft v0.14.0 — 修复NCard文字/费用/描述不显示

### 用户反馈
- 六张卡的卡面还是在容器的左上方，显示不全
- 卡面描述显示 "if you can read this, there is a bug"
- 费用无法显示，只有卡面的图片是对的
- 不会显示中文

### 根因分析
日志关键发现：
```
[NCard] Created native card for DraftId=0, Entry=STOMP, Scale=0.65, Title=Stomp  ← Title是英文！
ERROR: Parameter "data.tree" is null.  ← ScheduleDeferredLocaleRefresh 时 NCard 不在树中
ERROR: Error calling deferred method: 'GridContainer::_schedule_locale_refresh': Method not found.
```

**核心根因：NCard 的场景树生命周期不正确**

1. `NCard.Create()` 调用 `NodePool.Get<NCard>()` 从对象池获取预实例化的 NCard
2. `NodePool` 中的预热对象**不在场景树中**，所以 `_Ready()` 还未被调用
3. `NCard.Create()` 设置 `Model` → 触发 `Reload()` → 但 `Reload()` 第一行检查 `if (!IsNodeReady()) return;` → **静默跳过**
4. v0.13.0 的 `UpdateVisuals()` 调用同样因 `IsNodeReady()` 为 false 被跳过
5. 结果：只有图片正确（NCard 有一些默认显示），但标题/描述/费用都是占位符

**原生游戏代码（NCardRewardSelectionScreen）的正确做法：**
```csharp
NCard nCard = NCard.Create(card);
NGridCardHolder holder = NGridCardHolder.Create(nCard);  // 内部调用 AddChildSafely(nCard)
_cardRow.AddChildSafely(holder);  // holder(含NCard)加入场景树 → _Ready() 触发
nCard.UpdateVisuals(PileType.None, CardPreviewMode.Normal);  // 此时 IsNodeReady() 为 true
```

### 修复方案 — 两阶段卡片创建

重构 `PopulateCards` + `CreateNativeCardCell` 为两阶段：

**Phase 1 `CreateEmptyCardCell()`**: 创建空壳 cell（样式、点击、hover），加入 `_cardGrid`（已在场景树中）
**Phase 2 `PopulateCardInCell()`**: 在 cell 已在场景树的状态下：
  1. 先把 `cardContainer` 加入 `vbox`（vbox 在 cell 中，cell 在 _cardGrid 中 → 全在场景树里）
  2. 再把 `NCard` 加入 `cardContainer` → **NCard 进入场景树 → `_Ready()` 触发 → `Reload()` 执行 → 文字/费用/描述正确初始化**
  3. 然后调用 `UpdateVisuals(PileType.None, CardPreviewMode.Normal)` → 此时 `IsNodeReady()` 为 true → 正确更新

**Phase 3 `DeferredUpdateAllCardVisuals()`**: 延迟一帧再次调用所有 NCard 的 `UpdateVisuals()`，确保本地化完全加载

其他修复：
- 移除失效的 `_schedule_locale_refresh` CallDeferred（GridContainer 没有此方法）
- 移除失效的 `ScheduleDeferredLocaleRefresh()` 中的 `tree.ToSignal()`（data.tree null错误）
- `cardContainer.ClipContents = true` 改回（NCard Scale=0.65 后视觉尺寸是 195x274 不会被裁剪，但布局 Size 300x422 会溢出，ClipContents 裁掉的是不可见的布局溢出部分）
- 添加详细日志 `IsNodeReady={nCard.IsNodeReady()}, InTree={nCard.IsInsideTree()}`

- **根因**：v0.16.0 使用 `PivotOffset=(150,211)` + `Position=(-52.5,-73.85)` + `ClipContents=true`。虽然数学上视觉左上角应对齐 (0,0)，但 Godot 的 `ClipContents` **不考虑缩放变换**——它基于子节点的 Position/Size 裁剪，NCard.Position 为负值导致大量内容被裁剪
- **修复**（`PopulateCardInCell()`）：
  - `nCard.PivotOffset = Vector2.Zero` — 从左上角缩放
  - `nCard.Position = Vector2.Zero` — 左上角对齐容器左上角
  - `cardContainer.ClipContents = false` — 关闭裁剪
  - Scale 从 (0,0) 缩放后，视觉占据 (0,0)→(195,274)，完全匹配容器

### Bug 2：选卡界面无法呼出暂停菜单
- **问题**：SharedDraft overlay 的 `_dimBackground.MouseFilter=Stop` 阻止了所有低层级 UI 的输入
- **修复**：
  - 新增 `DraftInputHandler` 内部类（继承 `Node`），挂载到 CanvasLayer
  - `_UnhandledInput` 监听 Escape 键按下

  - 最大轮询 120 秒后超时兜底
  - `OpenPauseMenu()` / `RestoreFromPauseMenu()` 方法对，类似已有的 `OpenCardInspector` 模式

## SharedDraft v0.18.0 — 使用 SubViewport 彻底解决 NCard 卡面偏移

### 问题（v0.17.0 仍未修复）
- **现象**：NCard 视觉中心仍然在容器左上角，只能看到卡面的右下四分之一
- **根因分析**：NCard 内部的视觉内容**以其本地原点 (0,0) 为中心点**排布（类似 Sprite2D 的 centered 行为），而非从 (0,0) 作为左上角开始绘制。内容范围大约从 (-150,-211) 到 (150,211)。v0.13~v0.17 的所有 PivotOffset + Position + Scale 方案都基于"内容从左上角开始"的错误假设

### 修复方案 — SubViewportContainer + SubViewport
- **彻底绕过** PivotOffset/Scale/Position 的坐标数学：
  - `SubViewportContainer`：大小 = ScaledCardSize (195×274)，`Stretch=true` 自动缩放 viewport 内容
  - `SubViewport`：大小 = NCardDefaultSize (300×422)，`TransparentBg=true`
  - NCard 全尺寸 (Scale=1) 放置在 SubViewport 内部，`Position = NCardDefaultSize / 2 = (150, 211)`
- NCard 的视觉中心 (0,0) 对齐到 SubViewport 的中心 (150,211) → 完整卡面填满 viewport
- SubViewportContainer 自动将 300×422 viewport 下缩到 195×274 显示
- 不再需要手动 `nCard.Scale`、`PivotOffset`、`ClipContents` 等任何坐标操作

## SharedDraft v0.19.0 — 回归简单方案（Control + ClipContents + Scale）

### 问题（v0.18.0 测试反馈）
- **现象**：卡面左上角对齐正确了，但卡面太大，容器显示不完全（右侧和底部被截断）
- **关键发现**：v0.18.0 截图证实 **NCard 的视觉内容确实从 (0,0) 开始绘制**（标准 Control 行为）
  - 之前 v0.18 的"以原点为中心"假设是**错误的**
  - SubViewport 方案中 `nCard.Position = (150,211)` 把卡面推到了 viewport 右下方
  - SubViewportContainer 的 Stretch 没有按预期缩小显示

### 修复方案 — 回归最简单的直接缩放
- 放弃 SubViewport 方案，回到 plain Control 容器
- `cardContainer.ClipContents = true` — 裁剪 NCard 的布局溢出（NCard.Size=300x422 > 容器 195x274）
- `nCard.PivotOffset = Vector2.Zero` — 从左上角缩放
- `nCard.Position = Vector2.Zero` — 左上角对齐容器左上角  
- `nCard.Scale = (0.65, 0.65)` — 视觉占据 (0,0)→(195,274)
- **与 v0.17.0 的关键区别**：开启 `ClipContents=true`
  - v0.17.0 关闭 ClipContents 是因为错误地认为它会裁剪缩放后的视觉内容
  - 实际上：Godot ClipContents 裁剪的是子节点的**布局区域**（Position+Size），不是缩放后的视觉
  - NCard 的 Size=300x422 在 195x274 的容器中会溢出布局，但 Scale=0.65 后视觉只有 195x274

## SharedDraft v0.21.0 — 修复选卡后右上角 Deck Count 不刷新

### 问题
- **现象**：选卡成功后卡牌确实加入了牌组，但右上角 TopBar 的卡牌计数不刷新
- **v0.16.0 曾修复过**：当时的修复是把 `SharedDraftScreen.Hide()` 提到 `AwardCards()` 之前，认为是 CanvasLayer 遮挡导致的
- **但 bug 复现了**：说明根因不是遮挡问题

### 根因分析（反编译 sts2.dll 深度分析）

1. **`NTopBarDeckButton`** 监听的是 `CardPile.CardAddFinished` 事件来刷新 deck count（不是 `CardAdded`）
2. `CardPile.AddInternal()` 只触发 `CardAdded` 和 `ContentsChanged` 事件
3. `CardAddFinished` 必须通过 `CardPile.InvokeCardAddFinished()` 手动触发
4. **在原版游戏中**：`CardPileCmd.Add` 在卡牌有 NCard 节点且在桌面上时，会创建 `NCardFlyVfx` 动画，动画完成后触发 `InvokeCardAddFinished()`
5. **SharedDraft 的场景**：通过 `CreateCardFromEntry()` 创建的新卡牌 `oldPile == null`，且没有 NCard 节点在桌面上（`NCard.FindOnTable(card)` 返回 null）
6. `CardPileCmd.Add` 的逻辑：当 `oldPile == null` 且 `cardNode == null` 且 `targetPile == Deck`（非 CombatPile）时，**直接调用 `AddInternal()` 就返回了**，跳过了所有动画和 `InvokeCardAddFinished()` 调用
7. 结果：`NTopBarDeckButton.OnPileContentsChanged()` 永远不被触发 → deck count 不更新

### 修复方案
- 在 `AwardCardToLocalPlayer()` 中，`CardPileCmd.Add` 成功后，手动调用 `PileType.Deck.GetPile(card.Owner).InvokeCardAddFinished()`
- 这会触发 `NTopBarDeckButton.OnPileContentsChanged()` → 读取 `_pile.Cards.Count` → 更新 `_countLabel` 文字 + bump 动画

## SharedDraft v0.22.0 — 核心选牌流程重构（进入即选卡 + 多轮结算循环）

### 需求概述
从线性"等待所有人→选卡→结算→发牌"改为灵活的"进入即选卡→多轮结算循环"模式：
